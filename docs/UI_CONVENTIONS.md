# UI 규칙

이 문서는 프로젝트 전체 UI의 확정 기준이다. 신규 UI는 별도의 예외가 명시되지 않는 한 이 규칙을 따른다.

## 1. 계층과 이름

모달 UI는 다음 계층을 기본으로 한다.

```text
{Feature}Overlay
├─ ModalBackdrop
└─ ModalCard
   ├─ Header
   │  ├─ Label
   │  └─ CloseButton
   └─ Content
```

- 화면 전체를 덮는 팝업 루트는 `Overlay`로 끝낸다.
- 화면에 지속해서 존재하는 기능 영역은 `Panel`로 끝낸다.
- 재사용 표시 컴포넌트는 `View`, 클릭 가능한 컨트롤은 `Button`으로 끝낸다.
- Scroll Rect 계층은 `{Purpose}Scroll/Viewport/Content`로 통일한다.
- `GameObject`, `Image`, `Text (TMP)`, `BG`, `Popup`처럼 역할이 불분명한 이름은 사용하지 않는다.

## 2. 모달 닫기

- 일반 정보창은 바깥 영역 클릭 닫기를 기본으로 활성화한다.
- 구매·분해 등 결과를 확정하는 창과 강제 튜토리얼은 바깥 클릭으로 닫지 않는다.
- 하나의 모달은 `IModalDismissHandler.Dismiss()`라는 하나의 종료 경로만 가진다.
- X, 취소, 바깥 클릭, 시스템 뒤로 가기는 모두 같은 `Dismiss()`를 호출한다.
- `IModalDismissHandler`가 있는 모달의 상태 정리와 종료 애니메이션은 View가 소유하며,
  `ModalBackdropDismiss`는 해당 `Dismiss()`를 한 번만 호출한다.
- 별도 `IModalDismissHandler`가 없는 단순 Overlay만 `ModalBackdropDismiss`가 직접 비활성화한다.
- `ModalBackdrop`은 `Button`이 아니라 Raycast Target이 활성화된 `Image`를 사용한다.
- `ModalBackdropDismiss`가 카드 바깥 클릭을 판별하며, `ModalCard` 내부 클릭은 창을 닫지 않는다.
- `Dismiss()`는 창을 숨기기 전에 선택 항목, 미리보기, 임시 수량 등 일시 상태를 정리한다.
- 닫기 기능을 Inspector 영구 이벤트와 런타임 리스너에 중복 연결하지 않는다.

## 3. 뒤로 가기와 팝업 스택

### LobbyScene

- 열린 Overlay와 Panel은 공통 팝업 스택에 등록한다.
- 시스템 뒤로 가기는 가장 최근에 열린 UI부터 하나씩 `Dismiss()`한다.
- 최상단 UI만 입력을 받으며, 하위 UI에는 입력이 전달되지 않는다.
- 더 이상 닫을 UI가 없으면 게임 종료 확인 Overlay를 연다.
- 종료 확인에서 다시 뒤로 가기를 누르면 확인창만 닫는다. 실제 종료는 확인 버튼으로만 수행한다.

현재 구현은 `LobbyModalStack`이 `ModalBackdropDismiss` 활성화 순서를 관리하며,
스택이 비었을 때 `ExitConfirmationOverlay`를 연다. 중첩 모달에서는 최상단과 그 조상
컨테이너만 Raycast를 유지한다.

### GameScene

- 시스템 뒤로 가기는 유닛/몬스터 정보 Overlay를 먼저 닫고, 닫을 정보 UI가 없으면 일시정지 메뉴를 연다.
- 일시정지 메뉴가 열린 상태에서 다시 뒤로 가기를 누르면 메뉴를 닫고 전투로 복귀한다.
- 유물 선택처럼 반드시 결과를 선택해야 하는 Overlay와 전투 결과 화면은 뒤로 가기를 소비하며 닫지 않는다.
- 일시정지 메뉴는 기존 인스턴스의 표시 상태만 전환하며 중복 생성하지 않는다.

### 스택 정책

- 일반적으로 동시에 조작 가능한 모달은 하나만 허용한다.
- 상세 → 강화, 상세 → 교체처럼 이전 화면으로 복귀해야 하는 흐름은 이전 모달을 스택에 보존하되 입력과 Raycast를 중지한다.
- 현재 모달이 닫히면 스택의 직전 화면을 복원한다.
- 인벤토리 탭 전환처럼 이전 상태 복원이 필요 없는 흐름은 기존 모달을 닫고 교체한다.

## 4. 반응형 레이아웃

- Canvas 기준 해상도는 `1080 × 1920`, 모드는 `Scale With Screen Size`를 사용한다.
- 주요 영역은 Anchor와 Layout Group을 사용하고, 절대 좌표는 장식 요소에만 제한한다.
- 휴대폰 비율에서는 콘텐츠 폭을 가용 영역에 맞춘다.
- 태블릿에서는 ModalCard의 최대 폭을 제한하고 화면 중앙에 배치한다. 남는 영역은 Backdrop으로 처리한다.
- Item Grid는 열 개수를 명시하고, 너비가 달라질 수 있으면 `ResponsiveSquareGrid`를 사용한다.
- 장비 5열 Grid는 기준 셀 `125 × 125`, 최대 셀 `125 × 125`로 설정하고 좁은 화면에서만 축소한다.
- Scroll Content는 좌측 상단부터 배치하고 `ContentSizeFitter`로 세로 확장한다.
- Safe Area 처리는 개별 슬롯이 아닌 최상위 화면 컨테이너가 담당한다.

## 5. 디자인 토큰

1080 × 1920 기준 권장값은 다음과 같다.

| 구분 | 값 |
|---|---:|
| 기본 간격 단위 | 8 |
| 사용 간격 | 8, 12, 16, 24, 32, 48 |
| 최소 터치 영역 | 80 × 80 |
| 일반 버튼 높이 | 88 |
| 주요 행동 버튼 높이 | 100 |
| 모달 Header 높이 | 100 |
| Caption 글자 | 28 |
| Body 글자 | 32 |
| Button 글자 | 36 |
| Section Title 글자 | 42 |
| Modal Title 글자 | 48 |
| Backdrop 색상 | Black, Alpha 0.75 |
| 일반 카드 안쪽 여백 | 24 |
| 강조 카드 안쪽 여백 | 32 |

- 값은 직접 흩어 쓰지 않고 추후 `UIThemeSO` 또는 공통 Style Prefab으로 이동한다.
- 희귀도 색상은 `RarityPalette`만 사용한다.
- 선택 상태는 색상만으로 표현하지 않고 체크 아이콘, 테두리, 명도 변화 중 하나 이상을 함께 사용한다.

## 6. 전환 애니메이션과 입력

- Overlay 진입은 `0.18초` Fade In과 `0.96 → 1.0` Scale을 함께 사용한다.
- Overlay 종료는 `0.15초` Fade Out과 `1.0 → 0.98` Scale을 사용한다.
- 전환 중에는 하위 UI 입력을 차단한다.
- 전환 중 사용자가 입력하면 애니메이션을 즉시 최종 상태로 완료한다.
- 애니메이션을 완료시킨 입력은 버튼 클릭이나 바깥 클릭으로 다시 처리하지 않는다.
- 애니메이션 종료 시점과 GameObject 비활성화 시점을 공통 전환 컴포넌트가 관리한다.
- 반복 클릭으로 Open/Close 애니메이션이 중첩되지 않도록 현재 전환 상태를 보관한다.

## 7. 접근성

- 모든 터치 대상은 최소 `80 × 80`을 확보한다.
- 작은 아이콘 버튼은 시각 크기와 별개로 투명 Raycast 영역을 확장한다.
- 텍스트와 배경은 일반 텍스트 4.5:1, 큰 텍스트 3:1 이상의 명암 대비를 목표로 한다.
- 중요 상태는 색상 하나에만 의존하지 않는다.
- 동적 텍스트가 길어져도 버튼이나 슬롯 밖으로 잘리지 않도록 Auto Size의 최소·최대값을 지정한다.
- 현 단계에서는 Canvas 전체 사용자 배율은 고정하고, 추후 접근성 설정에서 글자 크기 단계를 제공할 수 있도록 Layout Group 기반으로 구성한다.

## 8. View 책임

- View는 상태를 표시하고 사용자 의도를 전달한다. 인벤토리·장비 데이터 변경은 Service 또는 UseCase가 담당한다.
- 장비 상세처럼 공통인 UI는 씬에 하나만 두고 호출자가 표시 데이터와 행동만 전달한다.
- 동적 UI는 재사용 Prefab 또는 명시적인 Runtime Factory 중 하나로 생성한다.
- View는 `OnEnable`에서 최신 상태를 다시 표시하고, `Dismiss()`에서 일시 상태를 정리한다.
- 비동기 처리 중에는 관련 버튼을 비활성화하고 중복 요청을 방지한다.

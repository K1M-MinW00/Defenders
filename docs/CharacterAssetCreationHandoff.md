# 신규 유닛·몬스터·보스 제작 인수인계

이 문서는 Defenders 프로젝트의 다른 채팅에서 신규 캐릭터를 기획하거나 제작할 때 그대로 공유하는 기준이다. 기획 채팅은 먼저 아래 규칙에 맞는 **디자인 잠금안**을 작성하고, 이미지 제작 채팅은 그 잠금안과 승인 이미지를 권위 있는 원본으로 사용한다.

## 다른 채팅에 붙여넣을 공통 지시문

```text
Defenders 프로젝트의 신규 유닛·몬스터·보스를 기획할 때 다음 규칙을 반드시 지켜줘.

1. 먼저 프로젝트의 기존 초상화, 게임 스프라이트, 애니메이션, Unity 메타데이터를 실제로 분석한다. 파일명만 보고 추측하지 않는다.
2. 제작 순서는 반드시 다음 승인 게이트를 따른다.
   기획 잠금안 → 컨셉 초상화 1장 → 사용자 승인 → 단일 Idle 스프라이트 1장 → 사용자 승인 → Idle → Move → Attack → Hurt → Die 순으로 애니메이션을 한 종류씩 제작·검수한다.
3. 초상화 승인 전에는 게임 스프라이트를 만들지 않는다. 단일 Idle 승인 전에는 애니메이션, 프리팹, 컨트롤러, 이펙트를 만들지 않는다.
4. 디자인 잠금안에는 역할, 체급, 실루엣, 신체 비율, 얼굴 구조, 눈 개수·색·위치, 장비와 착용 손, 고정 팔레트, 이펙트 색, 단순화 가능한 요소, 프레임마다 절대 바뀌면 안 되는 요소를 명시한다.
5. 비대칭 요소는 ‘왼쪽/오른쪽’이라고 모호하게 쓰지 말고 화면 기준 또는 캐릭터 기준을 명시한다.
6. 게임 스프라이트는 제한 팔레트 픽셀 아트다. 외곽선은 기본 1px의 어두운 색, 광원은 좌측 상단, 투명도는 0 또는 255, 모든 좌표와 변화는 정수 픽셀을 사용한다. 안티앨리어싱, 블러, 보간, 네온 발광, 반투명 가장자리를 금지한다.
7. 일반 캐릭터는 100x100 논리 셀, 16 PPU를 사용한다. 화면 오른쪽을 보는 측면 또는 약한 3/4 측면이 기본이며, 일반 발/하단 기준선은 원본 셀 y=56±2 부근이다.
8. 실제 크기는 캔버스가 아니라 불투명 바운드로 판단한다. 기존 같은 체급 캐릭터 최소 2개와 불투명 폭·높이를 비교하고, 16 PPU 월드 크기가 유사한지 검증한다.
9. 애니메이션에서는 얼굴, 눈, 신체 비율, 장비 구조, 장착 손, 방향, 팔레트, 기준선, 몸통 중심을 고정한다. 포즈는 같은 캐릭터의 안정된 부위를 이동해 만들며 프레임마다 새로 재해석하지 않는다.
10. Idle은 단순 상하 이동이 아니라 호흡에 따른 몸통·후드·의상 변화와 부속물의 미세한 후행을 사용한다. 변화량은 보통 1~2px 이내다.
11. Attack과 Die는 가장 높은 무기나 가장 넓은 포즈를 기준으로 전체 캐릭터를 축소하지 않는다. 중립 몸체 프레임을 승인 Idle 높이와 1px 이내로 맞추고, 무기·이펙트·쓰러진 자세가 셀의 추가 공간을 사용하게 한다.
12. 각 100x100 셀에서 이전/다음 프레임의 잘린 손, 무기, 의상, 이펙트 조각이 넘어오지 않았는지 검사한다.
13. 보스는 일반 100x100 그림을 확대하지 않는다. PPU 16은 유지하되 실제 픽셀 수와 셀을 함께 늘린다. 소형 보스 160x160, 표준 보스 192x192, 초대형 보스 256x256을 기본 후보로 삼고 실제 불투명 높이와 최대 동작 범위로 최종 선택한다.
14. 공격 이펙트나 투사체는 가능하면 본체와 분리한다. 투사체 애니메이션은 런타임 이동을 프레임 안에 표현하지 않고, 동일 앵커에서 내부 에너지 변화만 표현한다.
15. 이미지 생성 결과는 그대로 신뢰하지 않는다. 팔레트, 알파, 불투명 크기, 기준선, 중심, 얼굴·장비 일관성, 인접 프레임 조각을 수치와 확대 이미지로 검수한다.
16. Unity에서는 Sprite Mode Multiple, PPU 16, Point 필터, mipmap 없음, 무압축을 사용한다. 100x100 셀 전체가 아니라 각 셀의 실제 불투명 영역을 타이트하게 슬라이스하고, 논리 셀 좌표에서 계산한 커스텀 피벗으로 흔들림을 막는다.
17. Monster_Base 구조를 유지한다. Monster_Base.controller를 Animator Override Controller로 재사용하고 Monster_Idle, Monster_Move, Monster_Attack, Monster_Die를 교체한다. Body에는 SpriteRenderer, Animator, MonsterAnimationEvent를 유지한다.
18. Attack에는 실제 타격/발사 프레임에 OnAttackHit, 회수 종료 직전에 OnAttackFinished 이벤트를 넣는다. 투사체나 공격 데이터가 정해지지 않았다면 임의 설정하지 않는다.
19. 기획 단계의 결과물은 이미지가 아니라 아래의 ‘디자인 잠금안 템플릿’을 우선 작성한다. 내가 승인하면 이미지 제작 채팅에 넘길 수 있는 최종 프롬프트와 고정값 표를 제공한다.
```

## 프로젝트 공통 화풍

- SD/치비 비율의 읽기 쉬운 게임용 픽셀 아트다.
- 큰 실루엣과 역할을 먼저 읽히게 하고, 작은 장식은 최소화한다.
- 외곽선은 순수 검정보다 약간 색이 들어간 짙은 색을 사용한다. 기본 두께는 1px이다.
- 내부 명암은 제한된 단계로 나누고 좌측 상단 하이라이트를 유지한다.
- 색은 과도하게 선명하거나 네온처럼 튀지 않는 저채도 계열을 우선한다.
- 같은 재질은 애니메이션 전체에서 같은 팔레트 구간을 사용한다.
- 얼굴과 장비는 작은 해상도에서도 구분될 정도로 단순한 덩어리로 설계한다.
- 배경과 그림자는 기본적으로 포함하지 않으며 완전 투명 RGBA PNG를 사용한다.
- 초상화는 `Assets/Art/ThirdParty/RPG/Images/Portrait.png`와 현재 승인된 `portrait_*` 에셋을 우선 참조한다.
- 게임 스프라이트는 `Assets/Art/ThirdParty/RPG/Characters(100x100)`와 프로젝트의 승인된 신규 캐릭터를 참조한다.

## 제작 및 승인 순서

### 1. 기획 잠금

- 역할과 공격 방식이 실루엣에서 읽혀야 한다.
- 체급과 목표 불투명 높이를 먼저 정한다.
- 무기, 방패, 장식, 눈, 뿔, 날개 등의 개수와 위치를 고정한다.
- 비대칭 장비는 화면 기준 위치와 캐릭터 기준 손을 모두 기록한다.

### 2. 컨셉 초상화

- 투명 배경의 전신 SD 초상화 한 장만 만든다.
- 얼굴과 모든 주요 장비가 보여야 한다.
- 이 단계에서는 게임 스프라이트나 애니메이션을 만들지 않는다.

### 3. 단일 Idle 레퍼런스

- 승인된 초상화를 바탕으로 정확히 한 장만 만든다.
- 실제 게임 크기, 방향, 기준선과 팔레트를 검증한다.
- Nearest Neighbor 확대 미리보기로 사용자 승인을 받는다.

### 4. 디자인 잠금 패키지

- 승인된 단일 Idle 원본
- 불투명 실루엣 마스크
- 고정 팔레트
- 얼굴 확대 참조
- 장비별 확대 참조와 장착 위치
- 신체 비율, 기준선, 중심축, 방향

### 5. 애니메이션

- 기본 순서: `Idle → Move → Attack → Hurt → Die`.
- 서로 다른 애니메이션을 한 번에 생성하지 않는다.
- 기본 프레임 수: Idle 6, Move 8, Hurt 4, Die 4, 일반 Attack 6~9.
- 키 포즈를 먼저 검수하고 중간 프레임을 만든다.
- Idle/Move는 루프, Attack/Die는 비루프가 기본이다.

## 크기 규칙

| 체급 | 논리 셀 | 권장 실제 불투명 높이 | 용도 |
|---|---:|---:|---|
| 소형 | 100x100 | 14~18px | 작은 일반 캐릭터 |
| 중형 | 100x100 | 19~24px | 보통 유닛·몬스터 |
| 대형 | 100x100 | 25~31px | 큰 일반·엘리트 |
| 소형 보스 | 160x160 | 40~60px | 약 1.5~2배 체급 |
| 표준 보스 | 192x192 | 55~90px | 일반적인 대형 보스 |
| 초대형 보스 | 256x256 | 80~128px | 레이드급 |

- 모든 체급은 PPU 16을 유지한다.
- 보스 기준선은 셀 높이의 약 56% 지점이다.
- 긴 무기·날개·꼬리는 최소 12~16px의 안전 여백을 둔다.
- 큰 이펙트 때문에 본체를 축소하지 말고 이펙트를 분리한다.

## 즉시 반려 조건

- 얼굴, 눈 개수·위치, 장비 손 또는 방향이 바뀐다.
- 무기 길이·종류·문양이나 갑옷 부품 수가 달라진다.
- 팔다리 또는 장비가 생성·소실된다.
- 몸통·머리 크기가 인접 프레임에서 2px 이상 급변한다.
- 기준선이 의도 없이 2px 이상 흔들린다.
- 반투명 픽셀, 안티앨리어싱, 블러 또는 보간 흔적이 생긴다.
- 이전 프레임의 잘린 손·무기·이펙트가 다음 셀에 남는다.
- 공격의 큰 무기·불꽃 때문에 중립 몸체가 Idle보다 작아진다.
- 보스를 작은 원본의 확대본으로 만든다.

## Unity 연결 규칙

- 텍스처: Sprite (2D and UI), Multiple, PPU 16, Point, mipmap off, uncompressed.
- 시트는 가로형이며 `프레임 수 × 셀 너비`로 계산한다.
- 셀 내부 불투명 영역을 타이트하게 슬라이스한다.
- 프레임 이름은 `<Character>_<Animation>_<Index>`로 고정한다.
- 논리 셀 중심·기준선을 바탕으로 커스텀 피벗을 계산한다.
- 몬스터는 `Monster_Base.prefab` Variant와 `Monster_Base.controller` 기반 Override Controller를 사용한다.
- Attack 이벤트는 실제 동작을 보고 프레임별로 결정한다.
- 공격 컴포넌트는 필요한 발사점, 투사체, 데이터가 모두 확정된 뒤 연결한다.

# 데이터 및 Firebase 검증 체크리스트

## 1. 시작 및 인증

- 신규 익명 계정으로 로그인할 수 있다.
- 기존 계정으로 재접속하면 이전 데이터가 복원된다.
- `CreatedAt`은 최초 생성 후 바뀌지 않는다.
- 데이터 변경 시 `UpdatedAt`이 서버 시간으로 갱신된다.
- 정상 데이터로 재접속할 때 불필요한 전체 저장이 발생하지 않는다.

## 2. 사용자 데이터 정규화

테스트 계정에서만 Firestore 값을 임시로 변경한 뒤 재접속한다.

- 음수 골드·보석·연료가 0으로 복구된다.
- 0 이하 레벨과 음수 경험치가 복구된다.
- 중복 유닛과 중복 인벤토리 스택이 정리된다.
- 보유하지 않은 유닛과 중복 유닛이 편성 목록에서 제거된다.
- 진급·한계돌파·중복 재료가 허용 범위로 보정된다.
- null 컬렉션이나 누락된 데이터 섹션이 기본값으로 복구된다.
- 복구된 데이터가 Firestore에 다시 저장된다.

## 3. 기능별 저장

- 프로필 아이콘과 닉네임 변경이 즉시 저장된다.
- 훈련 시 재화·재료·유닛 성장이 함께 저장된다.
- 진급 시 재료와 유닛 정보가 함께 저장된다.
- 한계돌파 시 중복 재료와 단계가 함께 저장된다.
- 가챠 시 재화·모집권·천장·보유 유닛이 함께 저장된다.
- 연료 구매와 광고 보상이 저장된다.
- 부대 편성이 저장된다.
- 스테이지 진행도가 저장된다.

## 4. 우편함

- 우편 목록을 불러올 수 있다.
- 단일 수령과 전체 수령이 한 번만 처리된다.
- 우편 보상 직후 재화·인벤토리·유닛 UI가 갱신된다.
- 수령한 우편과 만료된 우편을 삭제할 수 있다.
- 가챠나 성장 작업과 우편 수령이 겹쳐도 데이터가 이전 값으로 돌아가지 않는다.
- 클라이언트 SDK에서 우편 생성을 시도하면 `PERMISSION_DENIED`가 발생한다.

## 5. 보안 규칙

- 자신의 `users/{uid}` 문서만 읽고 쓸 수 있다.
- 다른 UID의 사용자 문서와 우편함 접근이 거부된다.
- 사용자 문서 삭제가 거부된다.
- `CreatedAt` 변경이 거부된다.
- `UpdatedAt` 없이 사용자 데이터를 변경하면 거부된다.
- 우편의 `Claimed` 이외 필드를 클라이언트가 변경하면 거부된다.

## 6. 네트워크 및 오류

- 일시적인 Firestore 오류는 최대 3회만 재시도된다.
- 권한·인증·데이터 오류는 반복 재시도하지 않는다.
- 최종 실패 로그에 Repository 이름, 작업명, 예외가 표시된다.
- 저장 실패 후 메모리 데이터가 성공한 것처럼 변경되지 않는다.

## 7. 빌드 확인

- Android 또는 iOS 빌드에 `GMFirestoreService` 코드가 포함되지 않는다.
- Firebase 서비스 계정 JSON이나 비공개 키가 프로젝트와 빌드에 포함되지 않는다.
- `google-services.json` 및 iOS 설정 파일은 대상 Firebase 프로젝트와 일치한다.
- 실제 기기에서 앱 강제 종료 후 마지막으로 성공한 기능별 저장 상태가 유지된다.

## 알려진 한계

- 모바일 강제 종료 시 `OnApplicationQuit` 비동기 저장은 보장되지 않으므로 종료 시 전체 저장을 사용하지 않는다.
- 클라이언트 권위 구조에서는 수정 APK가 본인 재화 값을 조작하는 것을 보안 규칙만으로 완전히 차단할 수 없다.
- 서버 권위가 필요해지면 가치가 있는 보상과 결제를 Admin SDK 서버 또는 Cloud Functions로 이전한다.
